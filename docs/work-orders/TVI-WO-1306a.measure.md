### P1. What silicon does (RM0433 Rev 9, the pages above)
- **`NACKF`** is set at the ninth SCL pulse of the address byte (p1954, p2011), so the address phase lasts at least nine SCL periods after the START, each at least `[(SCLH+1) + (SCLL+1)] × (PRESC+1) × tI2CCLK` (p1971), plus `tSYNC1 + tSYNC2`, which RM0433 gives only by their causes (slopes, filters, two to three kernel clocks).
- **A STOP follows a NACK automatically, whatever `AUTOEND`** (p1975 is unconditioned). The WO's "with `AUTOEND` = 0 the bus waits" (from memory) is, I predict, not what the text says. `STOPF` is set once that STOP is on the bus (p2011: "the STOP condition is generated by the peripheral"), so after `NACKF`, by at least the STOP's own timing.
- **`TXIS` is not set** (p1975). **`TXE` and a `TXDR` flush on a NACK:** from memory, a NACK flushes `TXDR` and sets `TXE`; I expect the text not to say so in the controller section (§1 reads it).
- **`NACKIE`** gates `NACKF` onto the event interrupt (p1999).
- **A read transfer whose address is NACKed:** `NACKF` by p2011 (the address is a byte the controller transmits); the automatic STOP is stated only for the transmitter (p1975). I expect no sentence for the receiver.

### 2.2 What silicon does (RM0433 Rev 9)

| Behaviour | Text | Page |
|---|---|---|
| A byte is nine SCL pulses, the ninth the acknowledge | "The controller generates nine SCL pulses … Then the receiver sends the acknowledge bit to the transmitter with the ninth SCL pulse" | §47.4.4 **p1955** (my §0 said p1954) |
| The controller's SCL period | "tSCL = tSYNC1 + tSYNC2 + {[(SCLH+1) + (SCLL+1)] x (PRESC+1) x tI2CCLK}"; each tSYNC "depends upon" the slope, the analog filter, `DNF` × tI2CCLK and "two to three i2c_ker_ck periods" | p1971 |
| `START` cleared once the address is sent | "The START bit is reset by hardware when the target address is sent on the bus, whatever the received acknowledge value" | p1974 |
| **A NACK in the controller transmitter** | "When a NACK is received, the TXIS flag is not set and a STOP condition is automatically sent. The NACKF flag of the I2C_ISR register is set. An interrupt is generated if the NACKIE bit is set." **Not conditioned on `AUTOEND`**; Figure 556 (p1976) ends the flow at `NACKF` = 1 for either `AUTOEND` | p1975, p1976 |
| `NACKF` | "set by hardware when a NACK is received after a byte transmission. It is cleared by software by setting the NACKCF bit … cleared by hardware when PE = 0" | p2011 |
| `STOPF` | set "when a STOP condition is detected on the bus and the peripheral is involved in this transfer: as a controller, provided that the STOP condition is generated by the peripheral" | p2011 |
| `NACKCF` | "Writing 1 to this bit clears the NACKF flag" | p2012 |
| `NACKIE` | `NACKF` on the event interrupt (Table 400, Figure 569) | p2003, p1999 |
| `STOP` written by software | "This bit only pertains to controller mode. It is set by software and cleared by hardware when a STOP condition is detected or when PE = 0" | p2005 |
| Controller to target | "from controller to target mode upon arbitration loss or upon generating STOP condition" | p1954 |

**Not in the text** (each a question in §4):
- **the time from the NACK to the STOP and `STOPF`**: no figure. The STOP's own timings are bus parameters, not given here;
- **`TXE` or a `TXDR` flush at a NACK in controller mode**: the flush is described only for target mode (pp. 1963–1966). At an address NACK `TXDR` was never written (`TXIS` was never set), so `TXE` stays 1;
- **a NACK of the address of a read**: the controller receiver's text (p1979) speaks only of the NACK the controller itself sends after the last byte. `NACKF` "after a byte transmission" (p2011) covers the address byte; the automatic STOP is stated only for the transmitter;
- **`BUSY`** is a stock tag reading 0 (`1306` §2.3), before and after.

**The WO's "with `AUTOEND` = 0 the bus waits" (from memory) is not what p1975 says.** A STOP follows a NACK whatever `AUTOEND`. It matters: every measured absent `START` has `AUTOEND` = 0 (§2.1), so the acceptance's `AUTOEND` = 1 write covers a path neither firmware takes.

- **What decides ArduPilot is the gap between `NACKF` and `STOPF`.** With none, ChibiOS's `STOP` after its `ICR` write meets a port that has left controller mode, and `1306`'s rule refuses it. With any gap, the `STOP` lands while the automatic STOP is still pending; silicon clears the bit "when a STOP condition is detected" (p2005), so it adds nothing, and the model absorbs it.
- **Renode's scheduler keeps sub-quantum times:** with a 100 µs quantum, T's `NACKF` fired 90.42 µs and its `STOPF` exactly 10.00 µs later in the fixture; in P at 90.000 and 100.000 µs.
- **The pending `STOPF` is mostly cancelled:** ChibiOS clears `PE` for its next attempt before the STOP time ends, and `PE` = 0 resets the state machine (p1959), so in the armed run only 10 of 110 `STOPF` were ever set (C; T 13); in the fixture 58 of 58 (C, the shorter period).
- **P (the planted sequence):** with T, `ISR` reads `0x1` at the `START` and at +50 µs, `0x31` at +150 and +350 µs, and `0x1` after `ICR` = `0x30`, for `AUTOEND` = 1 and = 0 alike. With Z, `0x31` from the `START` on.
- **The armed run moves in time, not in outcome.** ArduPilot's 110 probes cost 23–95 µs instead of 4.0–4.4 ms, so its boot runs about 0.46 s ahead: EKF3 initialises at 6.76 s (`main` 7.23 s), its tilt alignment completes before the arm command, so one "PreArm: EKF attitude is bad" (8.50 s) is not sent, and the 1 Hz heartbeat's phase moves from .79 s to .33 s. The injected arm command (400) is accepted at 9.00 s on both (result 0); the first armed heartbeat is at 9.33 s (`main` 9.79 s). Heartbeats in the window: 18 (`main` 19), from the phase. One heartbeat at 11.33 s carries `base_mode` 217 (209 with `MAV_MODE_FLAG_GUIDED_ENABLED`, 0x08), 0.33 s after the injected mode change at 11.00 s, where `main`'s next one, at 11.79 s, carries 209: **not explained further.** The `TVI-ADC-LEVEL` records (530,175) are `main`'s, unchanged.

## 4. The stop (WO §1, §7), and the questions

**Stops.** §1's, with the measurement. Two of §7's conditions also bear:
- **The budget is at risk** (§2.6): an active NACK lets ArduPilot do about 38 % more in its 5 s budget boot. That passed at load 8.7 (+10.3 MiB) and refused twice at load 15–19 (+34.0, +42.2 MiB); the same code inactive passes (−5.7 MiB). CI's unshared runners should read the low-load figure; a refusal there is §7's stop.
- **An observer changes on a path RM0433 says is valid** only in this sense: ArduPilot's timeline (§2.3) and the faulted `sentinel-03` (§2.5), where a refusal goes away. No consumer verdict changes.

Nothing in the generated boots, ArduPilot's fixture or the armed run refuses under the timed models (T, C); every generated boot block is identical; the armed run still arms.

**Q1. `AUTOEND` = 0.** p1975 sends a STOP after a NACK whatever `AUTOEND` (Figure 556, p1976); the WO's "with `AUTOEND` = 0 the bus waits" was from memory. Every measured absent `START` but one (faulted `sentinel-03`'s W 3) has `AUTOEND` = 0.
- **Proposal:** model the STOP whatever `AUTOEND`, cited p1975. Plant both: the WO's `AUTOEND` = 1 write (acceptance) and an `AUTOEND` = 0 write (both firmwares' path), each reading `NACKF` and `STOPF` at their times and cleared by `ICR`.
- **Ask:** accept.

**Q2. When `NACKF` is set** (WO: "at the end of the address phase"; acceptance: "at the page's timing").
- **(a) Computed, C:** nine SCL periods after the `START` (p1955), each `[(SCLH+1) + (SCLL+1)] × (PRESC+1) × tI2CCLK + tSYNC1 + tSYNC2` (p1971), with each tSYNC at its stated floor, two kernel clocks plus `DNF` × tI2CCLK. The slope and analog-filter parts p1971 names have no figure here, so the time is a lower bound, named as such. The kernel clock comes from `I2C123SEL` (p416): `rcc_pclk1`, `pll3_r_ck`, `hsi_ker_ck`, `csi_ker_ck`. That needs the PLL arithmetic the USART and ADC guards each already carry (the ADC's handles PLL3). Inside the fence, it is a third private copy. A `START` whose kernel frequency has no rule (a PLL outside its ranges, an unread reference) refuses `unmodeled` at the `START`, as the USART's `TVI-USART-IDLE` does.
- **(b) The same, from a shared query** (`KernelHz` on the RCC guard for USART, ADC and I2C): one copy, but outside this WO's fence (the RCC, USART and ADC guards).
- **(c) Zero time, Z:** refuses ChibiOS's every probe (§2.3); not proposed.
- **Recommendation: (a)**, with (b) as a reduction row for a later WO.
- **Ask:** (a), (b) or (c).

**Q3. The time from `NACKF` to the STOP (`STOPF`).** RM0433 gives no figure (§2.2), and it is what decides ArduPilot (§2.3): any gap passes; none refuses.
- **Proposal:** one further SCL period by the same formula: inferred, not cited, and named so in the ledger and the record texts.
- **Ask:** accept, or another value.

**Q4. A firmware `STOP` while the NACK's STOP is pending** (ChibiOS's `CR2 |= STOP`, at every probe).
- **Proposal:** absorbed. The write is taken with `STOP` cleared, and no second STOP is passed to the stock model, which would set `STOPF` at once. Cited: "cleared by hardware when a STOP condition is detected" (p2005).
- **From the `START` to `STOPF`**, a `START`, a `TXDR` write or a `CR2` field change is `TVI-I2C-TRANSFER`, `unmodeled`, as `1306`'s open transfer is. No firmware does it: ChibiOS clears `PE` first.
- **`PE` cleared** (p1959) or **`Reset()`** cancels a pending `NACKF` or `STOPF`. ChibiOS does this before 100 of 110 armed-run STOPs.
- **Ask:** accept.

**Q5. `TVI-I2C-ABSENT` withdrawn** (WO (2)), for a write.
- Every write `START` to an address with no device on that port NACKs, on `i2c1`–`i2c3`. The `Absent` table, the ledger text that lists it (`NACKF`, `START` rows), `ledger`'s check of it and mutant `I238` go.
- **The records that change:** none in any replay of the 14 boots, the fixture or the armed run (all were acknowledged). **Faulted `sentinel-03`:** 3 × `TVI-I2C-ABSENT` on `main` become none. Any board whose platform lacks a sensor its firmware probes, outside the old table (`0x46`, `0x47`), changes the same way.
- **Ask:** accept.

**Q6. A read `START` to an absent address.** No firmware makes one (§2.1). `NACKF` follows from p2011, but RM0433 states the automatic STOP only for the transmitter (p1975).
- **(a)** Modeled as the write, by inference.
- **(b)** `unmodeled`, keeping the rule name `TVI-I2C-ABSENT` for a read only.
- **Recommendation: (b).**
- **Ask:** (a) or (b).

**Q7. A NACK in the data phase.**
- No device model in any measured platform NACKs a byte: Renode's `II2CPeripheral.Write` has no NACK, so the twin cannot produce one and there is no path to refuse.
- The ledger's `NACKF` row states "data-phase NACK: not modeled", as the WO says, and no firmware relies on it.
- **Ask:** accept.

**Q8. "Unknown slave at address N."** It is still written under the guard's name, once per absent `START`. C keeps every count (§2.3), so `absent_address` is unchanged on every board. **Ask:** accept.

**Q9. The form.**
- **The interrupt line:** the guard owns `EventInterrupt`, the stock line OR `NACKF`·`NACKIE` OR its own `STOPF`·`STOPIE`. It follows the stock line by `AddStateChangedHook`, as the USART guard follows its IRQ. The restatement is unchanged.
- **Reads:** `ISR` is served with the guard's `NACKF` and `STOPF`.
- **Clears:** `ICR.NACKCF` and `STOPCF` clear them.
- **The ledger rows:** `NACKF`, `NACKIE` and `NACKCF` become "modeled by the guard", cited p1975, p2011, p2012; the `START` row loses the acknowledgement.
- **Ask:** accept.

**Q10. The budget** (§2.6). The NACK lets ArduPilot's budget boot do more work in the same window; the overlay's code costs nothing measurable. Locally it passes at low load (+10.3 MiB) and refuses under load. **Proposal:** build, and let CI judge on its unshared runners, as `1201` rules; if CI refuses, stop with its medians (§7), with the like-for-like control (the inactive code) ready to report beside them. **Ask:** accept, or a different handling now.

**Q11. The shards** (§2.7): ten, 15.4 min a job at 1.53, `ci` 17.1–17.4 min. **Ask:** none needed; noted.
