### 5.2 The stock RCC, measured (for the record; ruled 13:45Z into FEEDBACK)

- **A write to `RCC_C1_*` (0x130–0x17C) is stored in the alias** and enables nothing. **A read of 0x17C is a stack overflow** (`STM32H7_RCC.cs` L1238; Renode aborts, exit 134).
- **A tag reads its reset bits, not 0.** `PLLCFGR` written 0 reads `0x01FF0000`. Architecture §2.0a's "read 0" is the architect's to correct.
- **`PLLxRDY` = `PLLxON`, whatever the reference;** `PLLSRC` = 11 still reads `PLL1RDY` = 1.
- **`*ENR` reads the bus-enable state,** 1 from reset (`APB2ENR` `0x00073033`). So a read-modify-write of an unregistered bit loses it: ArduPilot's `AHB2ENR` reads `0x40` on stock against silicon's `0xE0000040`.
- **`CFGR.SW` switches at once to a source that is not running, and with PLL1 and `DIVM1` = 0 divides by zero** (L108–114). That led to `TVI-RCC-SW`.

### 5.3 Consumer side (Aethelgard, Phase 2), measured, not changed

1. **RUL-09 (b): every RCC property goes on the guard's entry.** Three of the consumer's 15 platforms emit `rcc: hseFrequency …`, and with `rcc` cancelled it reaches nothing, with no error.
   - Measured: `hse16-trap` runs at 8 MHz, while `hse16` (on `tviburiRcc`) reads 16 MHz.
   - The stock Nucleo board does the same (8 MHz, harmless); Tviburi's board restates it.
2. **Its own `spi1`/`spi2` register on `rcc`** and must name the guard.
3. **The access log of `sysbus.rcc` loses register names** (`(unknown)`).
4. **The stock RCC's 2,403 warnings on ArduPilot's boot become sourceless.**
5. **The boot block's `AHB2ENR` changes** on ArduPilot (`0x40` → `0xE0000040`, silicon's value).

### 5.4 Backlog (the scope test: not built here)

- **CSleep is not modeled (A6).** A peripheral's clock runs across `WFI` whatever its `LPEN` says.
- **Every registered peripheral is enabled on the bus at reset in the stock model** (`*ENR` reads 1), while silicon's clocks are off and "a write access will be ignored" (p373). A firmware that never writes an enable passes in the twin. In the consumer's runs the cold writes zero every `*ENR` first (15/15 boots), so this applies to Tviburi's own monitor tests. Locking at reset breaks `conditions.resc` and 1200's generated SPI sweep (`tools/`). Put to the architect; a follow-up.
- **A kernel clock lost after a start:** asked of the architect (1300a or later).
- **`D1CKRDY`/`D2CKRDY` read 0** (stock tags); a firmware that polls them (p372 step c) stalls with no record. Neither firmware does.
- **`RCC_CSICFGR` (0x00C) is undefined in the stock model**, reading 0 where silicon reads `0x2000 00xx` (p390). **`PLL2DIVR`/`PLL3DIVR`** read back with each field's top bit dropped; no PLL2/3 frequency is modeled.
- **`HSEBYP` written with the HSE on** ("can be written only if the HSE oscillator is disabled", p384): the order is not checked.
