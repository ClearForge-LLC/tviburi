## 4. The adversarial pass (WO §5)

There were two passes: mine through the build, and an independent one by a fresh reviewer. The reviewer was given the code, the stock source and RM0433, not my conclusions. I checked each of its findings in the code and the manual before acting on it.

| WO §5 item | Result |
|---|---|
| `AOE` setting `MOE` on update | `AOE` = 1 refuses (`timer-aoe`); the guard's `MOE` changes only by a software write |
| A break input clearing `MOE` | `BKE`, `BK2E`, the break filters and polarities refuse unless 0 (`timer-fields`); no break input is modeled, so `MOE` is never cleared behind the guard |
| `CCxE` written in a sub-word | a 16-bit store merges into the word (`timer-half`, and the upper half in `timer-halfhigh`); an 8-bit store refuses (`timer-byte`, p1588) |
| `LOCK` bypassed by a reset | `machine Reset` and TIM1RST through the RCC both clear it, as silicon does ("frozen until the next reset", p1615): `timer-reset`, `timer-rccreset` |
| A gate that changes a consumer observer silicon would not change | none (§3) |
| A polarity applied twice | `timer-polarity` reads the stock line high and PA8 low. The stock model never applies `CCxP` to an output; `CCxNP` = 1 refuses |

**The independent review found three defects, all fixed in `3939ff4`:**
1. **A stale stock line.** The stock `CCRx` resets to `0xFFFF`, so in PWM mode 1 the stock line went high and stayed high. The guard only masked it, and a later `CCR` 0→N write, or `OCxM` frozen, brought the high back. **Fix:** the guard writes `CCRx` = 0 into the stock model at reset (p1610) and lowers the stock line when `CCRx` = 0 in PWM mode 1 (p1558). The copy of `CCRx` and the mask are gone. Covered by `timer-ccrreset`, `-ccr0` and `-ap-m`, and mutants TM05 and TM06.
2. **`CCxE` = 0 erased the stock OCxREF** (`STM32_Timer.cs` L695–704), so a force-active output re-enabled stayed low. Silicon computes OCxREF whatever `CCxE` says (p1607). **Fix:** the stock model sees every `CCxE` set, and the guard alone gates. Covered by `timer-reenable` and TM29.
3. **A zero-width pulse at reset:** the copies were cleared after the stock reset. **Fix:** the copies are cleared first. No test counts edges at a reset (a row, §7).

**The review also found test gaps, now closed:** TIM8's routes (`timer-tim8on`, TM30), the LOCK level boundaries (`timer-lockbelow`, `-lockbelow2`, TM25–TM27), and the upper half of a 16-bit store (`timer-halfhigh`, TM28).

**Documentation fixes from the review:**
- the `OISxN` rows no longer claim an output;
- `SR.UIF`/`CCxIF` are now `stock-wrong`: the stock model sets them only with their interrupt enabled, and silicon sets them always (p1597);
- the idle level cites OIS1 p1591, MOE p1614 and OSSI p1615;
- CCMR3's lock is stated as not applied (p1617 has no LOCK note).

**Also found and fixed:**
- **By the tests:** in recorded mode, a DMAR write also recorded a false "no register" field refusal.
- **By the review:** a refused LOCK change in recorded mode reached the copy. The frozen LOCK bits are now kept.
