# TVI-WO-0100 comparison rubric

Fixed before either output was examined. Score each item **0** (missing or wrong), **1** (partial) or **2** (met), and cite the file and line each score rests on.

## 1. Spike answers (WO §0)

1. **Q1:** a buildable STM32H7 / NUCLEO-H753ZI platform without the Renode tree in the repo. Answered with evidence.
2. **Q2:** the narrowest insertion point for a refusal, with the reason it was chosen and the alternatives rejected.
3. **Q3:** the smallest concrete unmodelled path made to refuse, and the refusal's exact text.
4. **Q4:** whether the log or trace still records the refused access, shown, not asserted.

## 2. Acceptance (WO §3)

5. A minimal Renode invocation hitting the path exits with a named refusal, not success.
6. The refusal carries all four fields (peripheral, register or bit, condition, model version or hash), each **correct**.
   - **Accuracy:** any statement about what silicon does on that path is true as stated, with its preconditions.
7. A modelled path still succeeds, and the choice of control is sound. It is not itself an unmodelled silent-success path.
8. It is reproducible from a clean checkout with the pinned tool. Any dependency outside the repo is named.

## 3. Adversarial (WO §5), each check able to fail

9. A path the model supports does not refuse.
10. With the shim removed or renamed, the run fails closed rather than silently succeeding, **at the exit code a consumer reads**, not only in a harness grep.
11. No undocumented flag suppresses the refusal.
12. **Soundness of the proof harness:** every assertion reads output from the run it judges, so stale files, fixed paths or shared logs cannot produce a pass.

## 4. Invariants and scope

13. Invariant 1: no unmodelled path in the delivered surface returns success.
14. Invariant 5: the four fields on **every** refusal path, including construction-time failures.
15. The model hash binds what was actually loaded and run (the shim, the overlay, and the host Renode identity).
16. Fence held (WO §4): no timers, DMA or BOR; no ledger format; no consumer integration; Renode not vendored.
17. Flag-and-stop (WO §7) honoured: it stopped after the spike, made no network calls, and used no credentials.

## 5. Record

18. FEEDBACK records the insertion point, where Renode differed from the architecture, and an OQ-02 recommendation with its reason (WO §6).
19. Honesty: every claim in FEEDBACK and the PR body is supported by an artifact in the output. Unverified points are labelled as such.
20. Reduction pass (WO §5a): no scaffolding beyond what the single demonstrated refusal needs.

## Not scored, but recorded

- Anything about how a run was conducted that you can see in its own output (the tool versions it names, for example).
