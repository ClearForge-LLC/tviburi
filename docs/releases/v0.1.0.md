## How to verify

1. **Pin the release hash** above. Never pin the tarball's name or a path (`RUL-10` (c)).
2. **Check the tarball's bytes against its `MANIFEST`,** with no Tviburi tool. `spike/2100/consumer-verify.sh TARBALL PIN [RENODE_ROOT]` is the reference, in POSIX `sh` with `sha256sum`:
   - the `MANIFEST`'s sha256 is the pinned hash;
   - `TviburiRelease.cs.template` matches its `file` line;
   - `Tviburi.cs`'s first n bytes match the `overlay` line, and its tail is the template with `@@MANIFEST_SHA256@@` replaced by the `MANIFEST`'s sha256;
   - `LEDGER.jsonl`'s first line names the release, and its other lines hash to `ledger-rows`;
   - the tarball holds exactly those four files, each once (no fifth or hidden member, no duplicate);
   - given the consumer's Renode root, its `Renode.dll` and `Infrastructure.dll` have the sha256s the `MANIFEST`'s `build` lines name. The strings alone cannot name the rebuilt `Infrastructure.dll` (`TVI-WO-2100.measure.md` §3).

   This is the binding check (`RUL-10` (f)). `tools/tviburi-release verify <dir> <pin>` does the same from a checkout.
3. **Hand Renode exactly those bytes:** `include @Tviburi.cs` before `mach create`, with the compiler cache off (`compiler-cache-enabled = False`, `RUL-10` (g)).
4. **Judge each run by its records:** a witness and an end from every guarded instance, each naming the pinned hash with `"mode":"enforcing"`, and no refusal (`RUL-12`). Renode's exit status is not a verdict.

## What it guards, and what it acknowledges

- **Guarded:** the eleven classes and their instances in the `MANIFEST`'s `class`, `restate` and `retype` lines (34 instances). Above `OQ-03`'s cut (ruled by Scotty 2026-11-26: the recommended cut), every path on the four flight paths is guarded or acknowledged by name: the motor, the clock tree, the sensor buses and the command links, with their DMA routes. Phase 1's gate is judged in `TVI-WO-1205.verdict.md`: **met**. Clauses 2–7 were met there, and clause 1 by `TVI-WO-1206`'s addendum (1,982 fields above the cut, 399 guarded, 1,583 read, 0 open).
- **Acknowledged:** every ledger row whose state is `acknowledged` or `inherited-unaudited` names its reason. Read the ledger by its hash (northstar invariant 7). The release's 1,834 field rows by state: 371 reserved, 315 tag, 307 guard, 299 acknowledged, 248 read-only, 143 stock-wrong, 83 inherited-unaudited (none above the cut, by `1206`'s per-field measure, `TVI-WO-1206.FEEDBACK.md`), 68 stock-undefined. The ledger also holds 37 model rows (10 guarded), 37 tag rows, 36 bench rows (all "not run") and 2 canned rows.
- **Not guarded:** every instance the ledger's `model` rows list without `guarded_by`. That includes TIM2–TIM17 except TIM1/TIM8, BDMA, DMAMUX2, which the stock platform does not model, the RTC, the NVIC and the watchdog.

## What the consumer must do

Every item is in `TVI-WO-1205.consumer.md`, by its id; read it there. Each line here only names the item:
- **A, pin it and prove which overlay ran:** A1 the release and ledger hashes; A2 the overlay's hash, compiler cache off; A3 refusing a missing, wrong or recorded witness; A4 the 1.5 GiB ceiling.
- **B, emit the platform from the class map:** B1 cancel and restate; B2 only what the manifest lists; B3 the RCC's properties on the guard; B4 the USART and SPI registrations; B5 the sensors' parent; B6 the `peripherals` kinds; B7 the `-> dmamux1@N` lines; B8 the generated platforms' PWR script; B9 the RCC's observable changes.
- **C, declare the board's properties:** C1 the crystal; C2 the revision; C3 the ADC levels; C4 the pulls and external levels; C5 the package; C6 the option bytes. The release's `property` lines name every property each guard takes.
- **D, run Renode and read the records:** D1 synchronous logging; D2 `RUL-11`'s grammar; D3 witness, end and no refusal; D4 `[ERROR]` lines alone; D5 the serial and flash readers; D6 the console budget.
- **E, judge accesses, not only records:** E1 `pc: "none"`; E2 DMA-moved accesses; E3 the non-`[cpu:]` writes; E4 the DMA guard's register names; E5 stamps; E6 the I2C "Unknown slave" line.
- **F, update its own prose and expectations:** F1 the NACK prose; F2 the unhandled-tag ledger rows; F3 the switchable pull-down; F4 ST's pin data; F5 the I2C storage rows; F6 the owned I2C instance's lines.
- **G** holds the rows carried past Phase 2.

All 37 items (A1–F6) and section G are checked against `TVI-WO-1205.consumer.md` as merged on `main` `8e15435`.
